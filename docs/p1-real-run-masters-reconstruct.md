## 这次真实运行发现并修好的问题

1. **母版逐字一致**：代理把标记行抄进提示词（`marker_included`）→ 提示里说明标记行不属于提示词。
2. **ImageGen 编数字**：S09 母版出现资料没有的“提升 2.6 倍”→ 重做 + 母版数字 OCR 检查（`master_qa.check_master_numbers`）。
3. **整页背景图走捷径**：r1 的 9 页里有 8 页背景残留原文字、0 个原生形状，旧门禁照样通过 → 加大图 OCR 残留检查和 v66“必须有原生形状”规则。
4. **PPTX 里有、渲染里看不见**：r3 的 S07 标题、0.26 被盖住 → 加渲染可见性检查（计划文字 + 母版上读得出的长行）。
5. **PowerPoint 比规范严格**：r4 的 S07 新建了 3 个图表，坐标轴 id 2226939960 超过 2147483647。XML 符合规范，PowerPoint 却拒绝打开整份文件。逐页拆开测试定位到 S07，再逐图表、逐改动测试定位到坐标轴 id。→ Worker 自动重编号（不改变可见内容，记录为 `worker_repairs`）；以后打不开时，Worker 逐页测试并告诉代理是哪几页。
6. **额度用尽时丢问题**：最后一次会话额度用尽，旧代码把未解决的问题清空，任务报成笼统的阻塞 → 改为“延后”，未解决问题带到下一次运行；会话失败也不再覆盖审核问题。
7. **恢复时先复查**：被延后或阻塞的任务恢复时，Worker 先审核磁盘上的现有文件；只剩 Worker 能修的问题时不花代理 token（本次 79 s 进 CP3）。
8. **OCR 小字误报**：S05、S08 的 12–14 px 小字肉眼可见，但 1 倍 OCR 读不出 → 看起来缺失的行先在 2 倍放大图上重读；母版上少于 6 个汉字的 OCR 行（多是图例和坐标轴拼在一起）不再当作丢失的文字。
9. **CLI 版本**：一次运行没有固定 `AUTOPPT_CODEX_BIN`，用到了 PATH 上的旧版 0.155.1，配置里的模型全部 HTTP 400。同一时刻（11:28）`~/.codex/config.toml` 的修改时间也变了，可能是旧版 CLI 启动时改写的，没有核实内容 → Worker 拒绝低于 0.163.0 的 CLI。
